# ADR-0004：compat 随能力迁移并删除

状态：已接受
日期：2026-09-03
取代：[ADR-0003：保留 compat 作为迁移桥梁](./ADR-0003-compat迁移桥梁.md)

## 背景

ADR-0003 将 `compat/antdv.ts` 和 `compat/icons.ts` 作为迁移桥梁，并计划在独立 P008 中统一评估和清理。随着 Adapter 边界稳定，独立清理阶段会延长临时接口存在时间，也会迫使后续阶段同时理解新旧两套规则。

## 决策

- compat 只是未迁移模块的内部施工依赖，不构成新版本的用户兼容承诺。
- 每项 UI 能力迁入 Adapter 后，在所属阶段立即删除对应 compat 导出、包装和重复默认值。
- P004 直接切换公共类型，P005 直接移除旧注册和解析规则，不增加废弃警告、兼容别名或双路径。
- Upload、Modal、服务和图标的 compat 由 P006 清理；Table 及最后剩余依赖由 P007 清理。
- 原 P008 的依赖扫描、架构保护和迁移记录分别并入 P004–P007，不再设统一兼容清理阶段。
- 原 P009 的第二 UI 框架验证并入 P005 的 Element Plus 最小 Adapter 和 P007 的简单 Table 验证。

## 后果

- 各阶段必须在同一轮中完成新能力、旧路径删除、回归验证和迁移记录，不把清理债务留给后续阶段。
- 中间提交仍需保持可构建、可验证；未迁移能力可继续内部使用 compat，但不得新增依赖。
- 旧公共 API 的移除属于下一大版本的直接不兼容变更，只提供明确迁移方式。
